# 비밀번호 보안 도구 (`26-w12-password`)

> 한국폴리텍대학 서울강서캠퍼스 사이버보안과 1학년 웹콘텐츠 제작 12주차 실습 결과물입니다.  
> 빈 저장소에서 `npm create vite`로 프로젝트를 직접 구성하고, **Web Crypto API**와 **k-익명성(k-Anonymity)** 기법을 활용한 비밀번호 보안 진단·생성·유출 확인 웹앱입니다.

---

## 소개

**ShieldPass (비밀번호 보안 도구)**는 사용자의 비밀번호 보안성을 다각도로 점검하고 관리할 수 있는 **사이버보안 전문 점검 대시보드**입니다.

- **실시간 보안 강도 진단**: 비밀번호 길이, 문자 조합, 정보 엔트로피(Entropy bit), 예상 해독 시간을 실시간 계산하고 연속 키보드 배열 등의 취약 패턴을 경고합니다.
- **안전한 비밀번호 생성기**: 예측 가능한 `Math.random()` 대신 하드웨어 엔트로피를 사용하는 `crypto.getRandomValues()` 기반으로 안전한 난수 비밀번호를 생성합니다.
- **k-익명성 기반 유출 확인**: Have I Been Pwned의 Range API를 활용하여, 비밀번호 원문은 일체 전송하지 않고 SHA-1 해시의 앞 5글자만 전송하여 10억여 건의 유출 데이터와 대조합니다.
- **영지식 AES-256-GCM 비밀 금고**: PBKDF2(100,000회 연산)로 마스터 키를 유도하여 메모를 브라우저 내에서 안전하게 암호화·복호화하는 확장 기능을 제공합니다.

## 나의 AI 기획·구현 과정

1. **AI 협업 방식**:
   - Antigravity IDE를 활용하여 전체 기능 요구사항(강도 분석, CSPRNG 생성기, k-익명성 통신, AES-GCM 금고)을 모듈별로 설계하고 단계적으로 구현하였습니다.
   - 보안 원칙(무전송 원칙, 최소 전송 원칙, console.log 및 localStorage 배제)을 프롬프트와 규칙(`AGENTS.md`)에 명시하여 보안 결함이 없는 코드를 작성하도록 유도했습니다.
2. **비밀번호 "강도"의 기준**:
   - 단순 길이뿐만 아니라 문자 다양성(대문자, 소문자, 숫자, 특수문자 각 포함 여부)을 점검합니다.
   - 키보드 연속 패턴(`qwerty`, `asdf`, `12345`), 반복 문자(`aaa`, `111`), 널리 알려진 사전 단어(`password`, `admin` 등)를 탐지하여 강도 점수에서 감점하도록 설계했습니다.
   - 문자 풀 크기($R$)와 비밀번호 길이($L$)를 기반으로 비트 엔트로피($E = L \times \log_2 R$)를 계산하고, 초당 100억 회 추측 가능한 오프라인 무차별 대입(Brute-force) 장비 기준의 해독 시간을 산출했습니다.
3. **구현 중 마주친 문제와 해결 방법**:
   - **대소문자 대조 오류 방지**: Have I Been Pwned의 응답 접미사(Suffix)는 모두 대문자 HEX로 전달됩니다. 클라이언트에서 생성한 SHA-1 해시를 반드시 `.toUpperCase()`로 변환하여 대조하도록 구현함으로써, 유출된 비밀번호가 안전하다고 잘못 판정되는 치명적인 취약점을 방지했습니다.
   - **네트워크 최적화 및 타이핑 노출 차단**: 글자를 입력할 때마다 실시간으로 네트워크 요청을 보내면 불필요한 트래픽이 발생하고 키 스트로크 타이밍이 노출될 수 있으므로, 사용자가 [유출 여부 확인하기] 버튼을 명시적으로 클릭했을 때만 요청을 보내도록 설계했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. **Math.random() 대신 crypto.getRandomValues()를 써야 하는 이유**:
   - `Math.random()`은 의사 난수 생성기(PRNG)로, 내부 시드 상태를 바탕으로 결정론적인 수열을 출력합니다. 이전 출력값 몇 개만 수집하면 공격자가 난수 알고리즘 상태를 복원하여 다음에 생성될 비밀번호를 쉽게 예측할 수 있습니다.
   - `crypto.getRandomValues()`는 암호학적으로 안전한 난수 생성기(CSPRNG)로서 운영체제의 하드웨어 엔트로피 풀(마우스 이동, 키보드 인터럽트 타이밍, CPU 클럭 노이즈 등)을 기반으로 하므로 미래의 난수를 수학적으로 예측할 수 없습니다.
2. **유출 확인 시 Network 탭에서 확인한 실제 요청 주소**:
   - `password` 입력 후 유출 확인 시 Network 탭에 기록된 실제 요청 주소:
     ```http
     GET https://api.pwnedpasswords.com/range/5BAA6
     ```
   - **검증 결과**:
     - 비밀번호 원문(`password`)은 물론, 전체 SHA-1 해시(`5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8`)조차 전송되지 않았습니다.
     - 오직 해시의 **앞 5자리(`5BAA6`)만 전송**되었으며, 서버로부터 해당 접두사를 공유하는 245개의 해시 접미사 목록을 받아와 브라우저 메모리 안에서 대조를 완료했습니다.
3. **k-익명성 방식으로도 서버가 알 수 있는 정보 (완전한 익명이 아닌 이유)**:
   - k-익명성은 비밀번호 원문과 정확한 해시값의 노출은 막아주지만, 서버는 다음과 같은 메타데이터를 수집할 수 있습니다:
     - **해시 앞 5글자(접두사)**: 사용자가 조회한 비밀번호가 속한 해시 버킷군.
     - **클라이언트 IP 주소 및 요청 시각**: 어느 네트워크의 사용자가 언제 조회를 수행했는지 파악 가능.
     - **응답 패킷 크기 분석**: 본 프로젝트에서는 이를 완화하기 위해 `Add-Padding: true` 헤더를 적용하여 서버가 더미 데이터를 섞어 응답 크기를 균일화하도록 방어했습니다.

## 나만의 확장 기능

1. **Add-Padding: true 트래픽 패딩 헤더 적용**:
   - Range API 요청 시 `Add-Padding: true` 헤더를 전송하여 서버 응답에 유출 횟수 0인 가짜 레코드를 포함시킵니다. 이를 통해 공격자가 응답 패킷의 바이트 크기를 스니핑하여 유출 목록의 크기를 유추하는 사이드 채널 공격을 무력화했습니다.
2. **영지식 AES-256-GCM 비밀 금고 (PBKDF2 + Web Crypto API)**:
   - 사용자의 마스터 비밀번호로부터 100,000회의 PBKDF2 해시 반복 연산을 거쳐 256비트 암호화 키를 유도하고, 12바이트 랜덤 IV와 함께 AES-GCM 인증 암호화(Authenticated Encryption)를 수행합니다.
   - 비밀번호가 단 1글자만 틀려도 AES-GCM 무결성 검증 태그가 불일치하여 복호화가 거부되는 영지식(Zero-Knowledge) 보안 원리를 직접 확인할 수 있습니다.
3. **취약 패턴 분석 및 엔트로피 계산기**:
   - 사전에 정의된 키보드 연속 패턴(`qwerty`, `12345` 등)과 연속 증가 문자열, 3회 이상 동일 문자 반복을 정규식 및 슬라이딩 윈도우 알고리즘으로 감지하여 실시간 경고를 제공합니다.
4. **대화형 사이버보안 원리 가이드 탭**:
   - 도서관 비유, 최소 전송 원칙, F12 개발자 도구 네트워크 탭 검증 가이드, k-익명성의 한계를 사용자가 한눈에 학습할 수 있는 가이드 화면을 내장했습니다.
